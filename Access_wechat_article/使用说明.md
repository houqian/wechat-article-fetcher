## 2. 方案 B：指定公众号 + 关键词筛选（推荐，你选的方案）

### 2.1 原理与约束
微信**没有公开的文章搜索接口**，要拿到某个公众号的历史文章列表，必须先用 **Fiddler 抓一次该号的 token**。
所以流程是：*每个目标公众号抓一次 token → 脚本自动拉列表、按关键词筛标题、下载命中文章并转 md*。
一次运行可连续处理多个公众号。

### 2.2 准备关键词
编辑 `keywords.txt`（每行一个，`#` 开头是注释）。脚本筛选「标题包含任一关键词」的文章，**不区分大小写**。
也可以在命令行直接传：`search_to_md.bat Agent 智能体 RAG`

### 2.3 首次启动 Fiddler：开启 HTTPS 解密（只需一次）
微信请求是 HTTPS，不开解密 Fiddler 看不到内容：
1. 启动 **Fiddler Classic**
2. 菜单 **Tools → Options → HTTPS**
3. 勾选 **Capture HTTPS CONNECTs** 和 **Decrypt HTTPS traffic**
4. 弹出"是否信任 Fiddler 根证书"点 **Yes**（再弹的 Windows 安全框也点 **是**）
5. 点 **OK**，**重启 Fiddler** 生效

### 2.4 获取公众号"主页链接"（关键！每个号一次）

> ⚠️ **这是最容易卡住的一步**。`profile_ext?action=home` 这条请求**只有打开"公众号主页/历史文章列表页"时才会产生**——只打开一篇文章是抓不到的。
> 所以要先拿到主页链接，发到微信里点开，才能在 Fiddler 里抓到 token。

**第 1 步：用工具算出主页链接**（不用 Fiddler）
- 双击 `run.bat` → 输入 `1` → 粘贴该号**任意一篇文章链接** → 回车
- 程序会打印一行 **"公众号主页"** 链接，形如：
  `https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz=XXXX==&scene=124#wechat_redirect`
- 复制这行链接

**第 2 步：在微信里打开它**
- 把上面的主页链接**粘贴到微信 PC 端的「文件传输助手」**并发送
- **点击**这条链接 → 微信会打开该公众号的**历史文章列表页**

### 2.5 抓 token
1. 抓之前先**清空 Fiddler**：工具栏 ✖ "Remove all"（列表干净好找）
2. 在微信里点开 2.4 第 2 步那条主页链接，让列表页加载
3. 回 Fiddler，按 **Ctrl+F** 搜 `profile_ext`，找到这条：
   - Host = `mp.weixin.qq.com`
   - URL 以 **`/mp/profile_ext?action=home`** 开头（含 `__biz`、`uin`、`key`、`pass_ticket`）
4. 选中该条，按 **Ctrl+U** 复制完整 URL

### 2.6 运行
- 双击 `search_to_md.bat`（或：激活环境后 `python search_md.py`）
- 按提示**粘贴刚复制的 token URL** → 选择拉取页数（回车=全部）
- 脚本显示命中清单 → 自动下载并转 md
- 完成后可选择「继续处理下一个公众号」，粘贴下一个号的 token 即可

> ⚠️ `key`/`pass_ticket` 有时效（约几十分钟～几小时），过期就重新抓一次（重做 2.4～2.5）。
> 请求过快可能触发限流，脚本已内置随机延时，**不要把页数设太大、跑太猛**。

### 2.7 输出
```
all_data/公众号----<名称>/
├── _命中清单.txt
└── <发布日期> <标题>/
    ├── article.md        ← Markdown（正文 + 本地图片）
    ├── index.html        ← 原始网页
    └── resources/images  ← 本地图片
```

## 3. 方案 A：已有文章链接，直接下载转 md（不用 Fiddler）

适合你已经手动收集好若干篇文章链接的情况。

1. 把链接逐行粘进 `urls.txt`（`#` 开头为注释），或命令行直接传链接。
2. 运行：`python download_md.py`，或 `python download_md.py https://mp.weixin.qq.com/s/xxxx ...`
3. 输出在 `all_data/markdown_articles/<序号>_<标题>/article.md`

## 3.5 汇总导出：按公众号归类，文件名=标题

下载/转换后的 `article.md` 是散落在各文章文件夹里的。想要一个统一、整洁、文件名即标题的版本：

```
python export_md.py            # 导出 all_data 下全部公众号
```
（或双击 `export_md.bat`）

输出：
```
导出_md/
  <公众号名称>/
    <文章标题>.md       ← 文件名就是文章标题
    assets/<图片>       ← 该号所有文章的图片(自动去重), md 内链接已改为 assets/
```

- 纯复制，不动 `all_data` 原文件；图片不会裂。
- ⚠️ 它只是搬运现有的 `article.md`。所以正确顺序是：**先 `to_markdown.bat` 重转（修大纲）→ 再 `export_md.bat` 导出**。

## 4.5 按公众号定制大纲规则（heading_profiles.json）

`html_to_md.py` 的标题识别分两层：

1. **通用视觉规则**（默认）：根据加粗/边框/居中等排版信号识别标题，适合大多数公众号。
2. **公众号专属文本规则**（`heading_profiles.json`）：有些号（如"东阳马生架构"）用纯文本编号
   排版——文首"大纲(N字)"块列出一级目录 `1.xxx ~ N.xxx`，正文原样重现这些行作章节标题，
   章节内再用 `(1)xxx` / `一.xxx` 分层。视觉规则对这种风格无效甚至会误判层级，
   所以按公众号名称配置专属规则；**命中 profile 的号自动跳过视觉规则**。

新适配一个公众号 = 在 `heading_profiles.json` 加一条，不用改代码：

```jsonc
"公众号名称": {
  "toc_marker": "^大纲\\s*[(（]\\d+字[)）]$",       // 文首目录块的标记行(可选)
  "rules": [                                         // 行首正则 -> 标题级别, 按序匹配
    { "pattern": "^\\d{1,2}\\.(?!\\d)\\S", "level": 2, "require_in_toc": true },
    { "pattern": "^[(（]\\d{1,2}[)）]\\S",  "level": 3 },
    { "pattern": "^[一二三四五六七八九十]{1,3}\\.\\S", "level": 4 }
  ],
  "max_len": 50,                                     // 超长的行不算标题
  "exclude_trailing_punct": "。！？!?；;，,、："       // 以句末标点结尾的行不算标题
}
```

内置的稳健处理：

- 标题行整行加粗（含被微信编辑器拆碎的 `**`）会先剥掉再匹配；
- 文首目录块粘连成一行（`3.xxx4.xxx5.xxx`）会按序号自动拆开，并校验序号衔接，
  防止把标题里的 `2.x` 这类文本误拆；目录块统一重排为 `- ` 列表；
- `require_in_toc: true` 表示该行必须出现在文首目录里才升级，防止正文编号行误判；
- 代码块（微信 code-snippet 结构）在转换前整体抽出、转换后回填为带语言标记的
  fenced block，换行/缩进完整保留，行号列噪声（`* * *`）一并清除。

改完规则后用 `python html_to_md.py all_data` 全量重转即可（纯本地，很快）。

## 5. 新增/改动的文件说明

| 文件 | 作用 |
|------|------|
| `html_to_md.py` | 把微信文章 `index.html` 提取正文 → Markdown，标题大纲还原 + 代码块还原(fenced+语言) + 图片映射到本地 |
| `heading_profiles.json` | 按公众号定制的文本编号大纲规则（见 4.5 节）|
| `download_md.py` | 方案A：给链接，直接下载+转 md |
| `search_md.py` | 方案B：token + 关键词 → 筛选 + 下载 + 转 md（支持 `--token` 非交互模式）|
| `get_home_link.py` | 由一篇文章链接算出公众号"主页链接"（用于抓 token）|
| `export_md.py` | 汇总导出：按公众号归类，文件名=标题，图片汇 `assets/` |
| `make_index.py` | 按 `categories.json` 生成分类索引 README |
| `keywords.txt` / `urls.txt` | 关键词 / 链接清单模板 |
| `run.bat` / `to_markdown.bat` / `search_to_md.bat` / `export_md.bat` | 一键启动（自动设 UTF-8 与内核路径）|

> 原项目代码未改动；以上均为新增。原 `requirements.txt` 已由 UTF-16 转为 UTF-8（否则 pip 安装报错）。

## 6. 作为 Skill 使用（推荐：按主题研究）

已封装为 Claude Code 技能 **`wechat-agent-research`**（位于 `~/.claude/skills/wechat-agent-research/`）。
以后在对话里直接说「研究 XX 主题，把相关公众号文章抓下来转 md 并建分类索引」即可触发，Claude 会按流程驱动。

约定与用法：
- **本仓库 = 引擎**（`src/` + `.venv` + Playwright + 各脚本），固定不动。
- **每个研究主题 = 一个独立子文件夹**，建在工作区根 `微信公众号文章获取\` 下、与引擎平级（如 `…\Agent\`、`…\RAG\`）。
- 在主题文件夹里运行引擎脚本（cwd=主题文件夹），产物 `all_data/`、`导出_md/` 落在该文件夹。
- 主题文件夹里放该主题的 `keywords.txt` 与 `categories.json`（分类名→标题关键词；见引擎根的 `categories.json` 示例）。
- `search_md.py` 非交互单账号：`python search_md.py --token "<profile_ext URL>" --pages 0`（关键词读 cwd 的 keywords.txt）。

> 现有的 Agent 主题数据已迁到 `微信公众号文章获取\Agent\`（引擎目录不再放 all_data/导出_md）。
